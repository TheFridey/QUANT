## C3: GBP database foundation

Request: authorise additive edits to `packages/shared/prisma/schema.prisma`, one new migration directory and database constraint tests for the following tables only. C3 depends on the account registry portion of C10. Review schema SQL before deployment; implementation approval does not authorise running migrations on production.

All identifiers are generated opaque text IDs; all foreign keys use ON DELETE RESTRICT and ON UPDATE RESTRICT. All event timestamps are timestamptz in SQL, mapped consistently by Prisma. Store provider event time and server receipt time separately. Money is GBP, booked Decimal(24,2); prices, stake, point size and calculated risk inputs Decimal(24,8), rejecting unrepresentable inputs before insertion. Financial calculation uses explicitly isolated Decimal precision. No float money columns.

Account FKs reference `AurumAccountIdentity`, whose `(accountId,currency,role,productFamily)` is unique and CHECK-constrained to GBP/AURUM_PAPER/GOLD_SPREAD_BET. Every economic row carries those discriminator columns and references that composite key. Account identity itself references a real PaperAccount ID with RESTRICT. `accountId <> 'primary'` alone is explicitly insufficient and is replaced by registered identity and composite ownership constraints. The existing PaperAccount USD columns are never used as GBP balances. The separate GBP ledger is authoritative; derived cash/equity must reconcile to it before entry admission. C10's additive AccountMembership table supplies actual owner membership (not an assumed existing registry).

Use the exact transition table already defined in `spread-bet-lifecycle.ts`: ENTRY_FILLED opens; ENTRY_REJECTED rejects; ENTRY_CANCELLED/ENTRY_EXPIRED cancel; EXIT_REQUESTED enters EXIT_PENDING; EXIT_FILLED closes at zero or PARTIALLY_CLOSED at positive remainder; EXIT_CANCELLED restores OPEN or PARTIALLY_CLOSED according to pre-exit stake; terminal states never reopen. FLATTEN and PROTECTION select CLOSE_LONG/CLOSE_SHORT according to registered position direction, never introduce alternate action enums. Partial entry fills are unsupported by this first lifecycle and must be refused atomically rather than invent a state.

Quotes require an additive immutable `GoldShadowQuote` evidence table (D11). Fill FK must point to immutable quote identity, not ephemeral buffer offsets. Until that table exists, C3 cannot claim complete fill provenance. Raw practice reference quotes remain non-executable; a separate simulation quote record carries scenario, reference identity and derivation hash. No execution route is introduced by these tables.

Exact additional C3 entity: `SimulatedSpreadBetQuote` has PK id, referenceQuoteId NOT NULL FK GoldShadowQuote.id RESTRICT, productId and immutable productVersionHash, scenario CHECK BASELINE/ELEVATED/SEVERE, bid/ask Decimal(24,8) with 0<bid<ask, pointSize positive Decimal(24,8), eventTime/receivedAt copied from reference, derivedAt server time, derivationHash SHA256, disclosure CHECK SIMULATION_DERIVED. Unique(referenceQuoteId,productVersionHash,scenario,derivationHash). `SpreadBetFill.quoteId` references this table's id RESTRICT; copied referenceQuoteId and product hash must agree via composite FK or a constraint trigger. The simulation record is immutable and never makes its reference executable. Fill admission still requires account/product/scope, latency and quality checks; a quote FK alone grants no eligibility.

Cancellation exception: CANCEL_ORDER has direction=NULL, stake=NULL, pointSize=NULL, stakeAtBooking=NULL and no economic fill. targetOrderId is required and composite FK(accountId,targetOrderId) references SpreadBetOrder(accountId,id), RESTRICT. It cannot target itself. Non-cancel actions require targetOrderId=NULL and direction matching their LONG/SHORT suffix. Cancellation cannot erase fills or release another account's reservations; cancellation effects and its audit event commit under the account/target-order locks.

Database CHECK/enum constraints validate known actions/states/currency and positive domains. Cross-row totals, valid transition ordering, risk limits, quote admission, gap pricing and margin headroom require transaction-level application enforcement plus DB triggers for immutable evidence and legal transitions. Account identity/config authorisation is application RBAC plus restricted DB write grants; possession of an account ID is never authorisation.

Transaction sequence: lock global emergency-stop row in shared mode; lock account-control row; account financial state; position; order; reservations. Re-evaluate pinned config and quote; append fill, cash ledger and margin movements; update materialised position/state and idempotency event in the same transaction. Every writer uses the same ordering. Global stop obtains an exclusive lock and commits before subsequent admissions. Existing in-flight transaction semantics must be explicitly tested; an uncommitted stop cannot retroactively undo a committed fill. No broker network call occurs in this transaction.

Migration sequence: (1) add C10 registry/control structures without backfilling or changing primary; (2) add quote identities; (3) add C3 entities, indexes and composite keys; (4) add checks, immutable-evidence and transition triggers; (5) test an empty DB and upgraded legacy fixture. No generated client files edited by hand. No account seeded automatically. Deploy migration separately before app code only after authorisation. Once any financial row exists, rollback is forward-only: preserve all new tables/history, disable new entries and deploy a compatible forward fix. Never drop populated financial tables or restore a stale dump over newer financial history.

Required DB tests: cross-account order/fill/position/reservation/ledger inserts rejected; wrong role/currency rejected; duplicate retry gives one economic event; concurrent reductions cannot over-close or release margin twice; lifecycle replay refused; crash before COMMIT leaves no partial fill; crash after COMMIT retries idempotently; GBP cash=sum(cash-affecting entries); equity=cash+marked unrealised (null on missing marks); partial close releases proportional reserved margin and preserves residual rounding; immutable financial events refuse UPDATE/DELETE/TRUNCATE. Test precision extrema and wrong-state transitions. These are acceptance tests to implement under approval, not claims of passing tests today.

Independent document review found inconsistent proposed enums, fabricated pending entry-price implications, an undefined ownership registry and ambiguous global-stop initialisation. These were corrected in this revision using existing scope/lifecycle enums, nullable pre-fill prices, explicit AccountMembership and unchanged legacy stop semantics. Migration SQL remains a protected implementation deliverable, not an existing reviewed artifact.
